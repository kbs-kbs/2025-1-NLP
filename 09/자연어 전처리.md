## 1. 자연어 처리란

- 우리가 일상에서 쓰는 언어의 **의미를 분석해 컴퓨터가 처리할 수 있도록** 하는 과정.
- 딥러닝 이해뿐 아니라 **인간 언어에 대한 이해**도 필요해 접근이 어렵다.
  - 영어는 띄어쓰기가 명확하지만 중국어는 없어서 단어 단위 임베딩이 어렵다.
- 영역별 완성도: 스팸 처리·맞춤법 검사는 완성도가 높고, **질의응답·대화**는 아직 발전이 필요한 분야다(그림 9-1).

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 말뭉치(corpus) | 자연어 처리 모델을 학습시키기 위한 데이터. 특정 목적에서 표본을 추출한 집합 |
| 토큰(token) | 문서를 나누는 단위 |
| 토큰 생성(tokenizing) | 문자열을 토큰으로 나누는 작업 / 그 함수가 토큰 생성 함수 |
| 토큰화(tokenization) | 텍스트를 문장·단어로 분리하는 것 |
| 불용어(stop words) | 문장에 많이 등장하지만 분석과 무관한 단어(a, the, she, he). 빈도 때문에 성능에 영향을 주므로 제거 |
| 어간 추출(stemming) | 단어를 기본 형태로 만드는 작업 (consign, consigned, consigning, consignment → consign) |
| 표제어 추출(lemmatization) | 품사를 고려해 사전에 있는 원형을 찾는 것 (am, are, is → be) |
| 품사 태깅(POS tagging) | 문장에서 품사를 식별해 붙이는 태그 |

- 품사 태그 예: VBZ(동사·3인칭 단수), PRP(인칭대명사), JJ(형용사), VBG(현재분사), NNS(명사 복수), CC(등위접속사), Det(한정사), Noun, Verb, Prep
- **형태소**: 언어를 쪼갤 때 의미를 가지는 최소 단위 (예: "되었습니다" = 어절 / "되" = 형태소)

## 3. 자연어 처리 4단계 (그림 9-6)

```
자연어(입력 텍스트) → 전처리 → 임베딩 → 모델/모형 적용(분류·예측)
                        │        │            └ 결정 트리, SVM
                        │        └ 단어 → 벡터 변환
                        └ ① 토큰화 ② 불용어 제거 ③ 어간 추출 ④ 정규화
```

## 4. 라이브러리

| 라이브러리 | 주요 기능 |
|---|---|
| **NLTK** | 교육용. 말뭉치, 토큰 생성, 형태소 분석, 품사 태깅 |
| **KoNLPy** | 한국어 형태소 분석. 꼬꼬마·코모란·한나눔·트위터(Okt)·메캅을 한 번에 설치하고 같은 방법으로 사용 |
| **Gensim** | Word2Vec(임베딩), 토픽 모델링, LDA |
| **사이킷런** | `CountVectorizer`(등장 횟수), `TfidfVectorizer`(TF-IDF), `HashingVectorizer`(해시로 실행 시간 감소) |

- KoNLPy는 내부적으로 JVM을 쓰므로 **Oracle JDK → JPype1 → KoNLPy** 순으로 설치한다(우분투는 명령 한 줄).

## 5. 전처리 ① 결측치

- 결측치 = 데이터가 없는 값(NaN). 예제는 `class2.csv`.
- 확인
  - `df.isnull()` → 결측치 여부, `df.isnull().sum()` → 열별 개수
  - 비율 확인: `df.isnull().sum() / len(df)`
- 처리 방법

| 방법 | 코드 | 비고 |
|---|---|---|
| 모든 값이 NaN인 행 삭제 | `df.dropna(how='all')` | 해당 행이 없으면 아무것도 지워지지 않음 |
| NaN이 하나라도 있으면 행 삭제 | `df.dropna(how='any')` | 가장 많이 쓰는 방식(데이터가 많을 때) |
| 특정 값으로 채우기 | `df.fillna(0)` | 0, 평균값, 최빈값 등 |
| 열의 평균으로 채우기 | `df.fillna(df.mean())` | 데이터가 적을 때 |
| 열 자체 삭제 | `del df['열']` | 데이터가 거의 없는 특성 |

- 정리: **데이터가 많으면 삭제**, **적으면 평균·최빈값·앞뒤 값으로 대체**.

## 6. 전처리 ② 토큰화

| 종류 | 방법 |
|---|---|
| 문장 토큰화 | 마침표(.), 느낌표(!), 물음표(?) 기준으로 분리 (`sent_tokenize`) |
| 단어 토큰화 | 띄어쓰기 기준 분리 (`word_tokenize`) |
| 아포스트로피 처리 | `WordPunctTokenizer` → it's → it, ', s / don't → don, ', t |
| 한글 토큰화 | KoNLPy의 Twitter(Okt) 형태소 분석기. 예제는 `ratings_train.txt` |

## 7. 전처리 ③ 불용어 제거 · ④ 어간/표제어 추출

- 불용어는 효율을 떨어뜨리고 처리 시간을 늘리므로 **반드시 제거**한다. NLTK의 `stopwords` 목록 사용.
- 어간 추출 vs 표제어 추출

| 항목 | 어간 추출 | 표제어 추출 |
|---|---|---|
| 품사 고려 | 안 함 | 함(같은 품사여야 가능) |
| 사전 | 없어도 됨 | 사전에 있는 단어만 |
| 예 | Automates, automatic, automation → automat | am, are, is → be |
| 알고리즘 | 포터(Porter), 랭커스터(Lancaster) | WordNetLemmatizer |
| 성능 | 랭커스터는 단어를 너무 축소해 정확도가 낮다 | 일반적으로 더 좋지만 시간이 더 걸린다 |

## 8. 정규화(Normalization) 네 가지

- 특성마다 값의 범위가 다르면(예: MonthlyIncome 0~10000 vs RelationshipSatisfaction 0~5) 큰 값이 더 큰 영향을 준다. **값의 크기 = 중요도가 아니므로** 스케일을 맞춘다.

| 방법 | 원리 | 주의 |
|---|---|---|
| `MinMaxScaler` | 모든 값을 0~1로 | **이상치에 매우 민감**(좁은 범위로 압축) |
| `StandardScaler` | 평균 0, 분산 1 | 가장 일반적 |
| `RobustScaler` | 중간값(median)과 IQR 사용 | 이상치에 덜 민감 |
| `MaxAbsScaler` | 절댓값이 0~1(−1~1) | 양수 데이터는 MinMax와 유사, 이상치에 민감 |

- 사분위수: Q1(25%)·Q2(50%)·Q3(75%), IQR = Q3 − Q1

## 9. PyTorch 데이터셋·데이터로더 (교안 후반)

- 전처리한 데이터를 **배치 단위**로 나누고 무작위로 섞어 학습하려면 PyTorch의 `Dataset`/`DataLoader`를 쓴다.
- 데이터가 많을 때 주로 사용하고, 적으면 꼭 쓸 필요는 없다. 여러 GPU로 병렬 학습도 가능하다.
- 네트워크는 배치 정규화(batch normalization)가 포함된 선형 계층으로 구성.
- 손실 함수: 이진 분류에서 `BCELoss`(시그모이드 포함) 또는 `BCEWithLogitsLoss`(BCELoss + 시그모이드 결합).
- 성능 측정 시 `torch.round()`로 확률을 0/1로 반올림해 비교한다.
- 예제(당뇨병 데이터 769건)에서는 데이터가 적어 테스트 오차가 획기적으로 줄지는 않았다.
