## 1. 임베딩이란

- 사람이 쓰는 언어(자연어)를 컴퓨터가 이해하는 **숫자(벡터)** 로 변환한 결과 또는 그 과정.
- 역할
  - 단어·문장 간 **관련성 계산**
  - 의미적·문법적 정보의 함축 (왕–여왕, 교사–학생)
- 방법에 따라 **희소 표현 기반 / 횟수 기반 / 예측 기반 / 횟수·예측 기반** 네 계열이 있다.

## 2. 희소 표현 기반 — 원-핫 인코딩

- 단어 N개를 각각 **N차원 벡터**로 표현. 해당 위치만 1, 나머지는 0.
  - 딕셔너리 [calm, fast, cat] → fast = `[0, 1, 0]`
- 치명적 단점
  1. 두 단어 벡터의 내적이 0 → **직교(orthogonal)** → 유의어·반의어 관계를 표현하지 못하고 서로 독립이 된다.
  2. **차원의 저주(curse of dimensionality)** — 단어가 늘면 차원이 끝없이 커진다.
- 대안: 워드투벡터(Word2Vec), 글로브(GloVe), 패스트텍스트(FastText)

## 3. 횟수 기반 임베딩

### 카운터 벡터(CountVectorizer)

- 문서 집합에서 단어를 토큰으로 만들고 **출현 빈도수**로 벡터를 만든다 → 토크나이징 + 벡터화를 동시에.
- `CountVectorizer()`가 하는 일: ① 문서를 토큰 리스트로 ② 각 문서의 토큰 빈도 계산 ③ 문서를 벡터로 변환
- `stop_words='english'` 옵션으로 불용어를 제거한 카운터 벡터도 만들 수 있다.

### TF-IDF

- 정보 검색(IR)에서 가중치를 구할 때 쓰는 알고리즘.
- **TF**(Term Frequency) = 문서 d에서 단어 t가 나온 횟수
- **DF**(Document Frequency) = 단어 t가 나타난 **문서 수**
- **IDF**(Inverse Document Frequency) = DF의 역수. 전체 문서가 많아질수록 값이 커지므로 **로그**를 취한다.
- 모든 문서에 나오는 a, the 같은 단어는 가중치를 낮춘다.
- **스무딩(smoothing)**: 전체 문서에서 단어 빈도가 0이면 분모가 0이 되므로 **분모에 1을 더하는 것**.
- 사용처: 키워드 검색 엔진, 중요 키워드 분석, 검색 결과 순위 결정
- `TfidfVectorizer()` → 코퍼스를 TF-IDF 행렬로. 문서 내 빈도가 높고 전체 문서에 포함된 문서가 적을수록 값이 크다.

## 4. 예측 기반 임베딩 — Word2Vec

- 신경망으로 특정 문맥에서 어떤 단어가 나올지 **예측하며** 단어를 벡터로 만든다.
- 의미가 비슷한 단어의 벡터가 2차원 그래프에서 가깝게 표현되며, '가깝다'는 **코사인 유사도**로 측정한다.
- 윈도우(window)로 나눈 텍스트를 (대상 단어, 컨텍스트) 쌍으로 신경망에 공급.

| 방식 | 방향 | 예 |
|---|---|---|
| **CBOW** | 주변 단어들 → 가운데 단어 예측 | "calm cat on the sofa" → "slept" 예측 |
| **skip-gram** | 가운데 단어 → 주변 단어 예측 | "slept" → 앞뒤 단어 유추 |

- CBOW 신경망: 은닉층 크기 N = 임베딩 벡터 크기. 입력–은닉 가중치 `W`는 V×N, 은닉–출력 가중치 `W′`는 N×V (V = 단어 집합 크기).
- `Word2Vec` 파라미터: 데이터셋 / `min_count`(최소 빈도) / `vector_size`(임베딩 차원) / `window`(컨텍스트 크기) / `sg`(0=CBOW, 1=skip-gram)
- 실습 결과(피터팬 `peter.txt`)
  - CBOW: peter–wendy 유사도 ≈ 100%, peter–hook ≈ 1% 미만
  - skip-gram: peter–wendy 40%, peter–hook 52%
  - 어느 쪽이 더 좋다고 단정하지 않고 **데이터 성격·접근법·목표**에 따라 고른다.
- 워드투벡터는 무작위 초기화와 무작위 처리 때문에 실행마다 결과가 책과 다를 수 있다.

### FastText

- 워드투벡터의 단점을 보완하려고 페이스북이 개발.
- 워드투벡터의 문제: ① 사전에 없는 단어(OOV)는 벡터를 얻을 수 없음 ② 빈도가 낮은 단어의 정확도가 낮음
- 해결: 단어를 **n-그램(부분 단어, subword)** 으로 쪼개 임베딩한다.
  - n=3(트라이그램)이면 'This is Deep Learning Book' → This is Deep / is Deep Learning / Deep Learning Book
  - 모르는 단어도 n-그램 조각과의 유사도로 의미를 유추할 수 있고, **노이즈에 강하다**.
- n-그램 용어: n=1 유니그램, n=2 바이그램, n=3 트라이그램
- 파라미터는 Word2Vec과 같다(vector_size, window, min_count, epochs).
- 사전 학습 모델: facebook의 wiki 벡터(294개 언어), 한국어는 `wiki.co.vec`.

## 5. 횟수·예측 기반 — GloVe

- 횟수 기반(LSA)과 예측 기반(Word2Vec)의 단점을 보완.
- 단어의 **전역 동시 발생 확률(global co-occurrence statistics)** 을 포함한다.
- 실습: `glove.6B.100d.txt`(100차원) → `glove2word2vec()`로 워드투벡터 형태로 변환 후 기존 함수 사용.
- 결과 예: 'bill' → clinton, 'cherry' → berry·blossom, woman + king − man → **queen**, tall/tallest → long/**longest** 유추.

## 6. 트랜스포머 어텐션 (10.2)

- **어텐션**: 인코더의 모든 은닉 상태(hj)가 디코더의 현 시점 은닉 상태(si)와 **얼마나 관련 있는지(어텐션 스코어)** 를 구해 → 소프트맥스로 **시간의 가중치(aij)** → 은닉 상태와의 **가중합 = 컨텍스트 벡터(ci)**.
- 기존 인코더-디코더는 컨텍스트 벡터가 **고정**이지만, 어텐션은 **시점마다 컨텍스트 벡터가 달라진다**.
- **트랜스포머**(2017, "Attention is All You Need"): 인코더·디코더를 여러 개 중첩한 구조(각각을 블록이라 함).
  - 인코더 블록 = 셀프 어텐션 + 전방향 신경망
  - 디코더 블록 = 셀프 어텐션 + 인코더-디코더 어텐션 + 전방향 신경망
- **seq2seq**: 입력 시퀀스 → 출력 시퀀스(번역). 시퀀스 레이블링(품사 판별)과 달리 입출력 길이가 다를 수 있다.
  - PyTorch 구현: 인코더(임베딩+GRU) / 디코더(임베딩+GRU+선형+소프트맥스), `teacher_force`(정답 단어를 다음 입력으로), `NLLLoss` vs `CrossEntropyLoss`(LogSoftmax + NLLLoss 포함)
  - 어텐션을 적용해도 이 예제에서는 성능이 좋아지지 않았다 → **어텐션 효과는 시퀀스가 길수록 크다.**
- **BERT**(2018, 구글): 트랜스포머 **인코더만** 쌓은 양방향 사전 학습 모델.
  - 입력: `[CLS] 문장 [SEP]`, 토큰화 → 각 토큰에 고유 ID 부여(빈자리는 0)
  - 버전: BERT-base(L=12, H=768, A=12), BERT-large(L=24, H=1024, A=16)
  - 실습: 네이버 영화 리뷰, `bert-base-uncased`(영어), 학습 데이터 10%만 사용 → 성능 낮음. 평가는 혼동 행렬 + `classification_report` + heatmap.

## 7. 한국어 임베딩 (10.3)

- 원리는 영어와 같다. `bert-base-multilingual-cased`(100개 이상 언어) 사용.
- 문제: 다국어 BERT 토크나이저는 한국어를 **너무 잘게** 쪼갠다(예: 고양이 → 고##, #양#, ##이). '사과'도 4·5·15·16·26·27 등 여러 토큰으로 나뉜다.
- 은닉 상태 shape `[13, 1, 33, 768]`(계층, 배치, 토큰, 유닛) → 배치 제거·`permute` → 토큰별 벡터 → 계층 결합(4개 계층 × 768 = 3072)
- 문장 벡터: 각 토큰의 두 번째~마지막 은닉 계층을 **평균**내어 768차원으로 만든다.
- '사과가 많았다 / 나에게 사과했다 / 사과를 먹었다'의 코사인 유사도를 구해 보면 다국어 BERT로는 정확한 구분이 어렵다 → **KoBERT** 같은 국내 모델이 더 정확하다.
- 결론: 임베딩 방법만 알면 **언어와 무관하게** 단어/문장 임베딩 → 모델 생성·훈련 → 예측·분류가 가능하다.

## 8. 시험 포인트

- TF·DF·IDF 정의와 스무딩 공식
- CBOW와 skip-gram의 차이
- 원-핫 인코딩의 두 가지 단점(직교성, 차원의 저주)
- FastText가 OOV를 해결하는 방법(n-그램)
- 어텐션에서 컨텍스트 벡터가 고정이 아닌 이유
- BERT는 트랜스포머 인코더만 사용, `[CLS]`/`[SEP]` 토큰
